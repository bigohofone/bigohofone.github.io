# Preserving Diversity in Synthetic Data: 모델이 만든 데이터로 모델을 학습시킬 때 다양성이 무너지는 이유와 그것을 지키는 방법에 대한 긴 노트

When a model is trained repeatedly on data generated by other models, the distribution of its outputs tends to narrow. Rare modes disappear first, then the tails shrink, and eventually the model produces a handful of "safe" answers for almost every prompt. 이 현상은 흔히 model collapse 라고 부르며, 합성 데이터의 비율이 높아질수록 더 빨리 나타납니다. The question is not whether diversity decreases, but which parts of it we can afford to lose and which parts we must protect.

## Why diversity collapses

There are at least three mechanisms that compound each other:

1. **Sampling bias.** Decoding with low temperature or top-$p$ truncation removes low-probability tokens, so the next generation never sees them.
2. **Filtering bias.** Quality filters (reward models, LLM judges) prefer typical, fluent outputs and quietly drop unusual but valid ones.
3. **Optimization bias.** Objectives like RLHF push probability mass toward high-reward modes, which sharpens the distribution even further.
   - This is especially visible in non-verifiable tasks such as creative writing.
   - 검증 가능한 과제(수학, 코드)에서는 정답이 여럿일 때 문제가 됩니다.

> Diversity is not noise to be removed; it is information about the space of valid answers.
> 다양성은 지워야 할 잡음이 아니라, 가능한 정답의 공간에 대한 정보다.

### Measuring it

A simple measure is the entropy of the output distribution. For a prompt $x$ and samples $y_1, \dots, y_n$ from the model,

$$
H(Y \mid x) = -\sum_{y} p(y \mid x) \log p(y \mid x)
$$

In practice we estimate it with embedding-based metrics instead, because exact probabilities over long sequences are intractable. `distinct-n`, `self-BLEU`, and embedding cosine similarity are the usual suspects.

## A small experiment

The following script generates samples at different temperatures and reports a distinct-2 score. 코드 블록이 길어질 때 가로 스크롤이 어떻게 보이는지도 확인하려고 일부러 긴 줄을 넣었습니다.

```python
from collections import Counter

def distinct_n(samples: list[str], n: int = 2) -> float:
    ngrams = Counter()
    for text in samples:
        tokens = text.split()
        ngrams.update(zip(*(tokens[i:] for i in range(n))))
    return len(ngrams) / max(1, sum(ngrams.values()))

for temperature in [0.2, 0.7, 1.0, 1.3]:
    samples = [model.generate(prompt, temperature=temperature, max_new_tokens=256) for _ in range(64)]  # a deliberately long line to test horizontal scrolling
    print(f"T={temperature:.1f}  distinct-2={distinct_n(samples):.3f}")
```

Running it on a 7B model gives the numbers below.

| Temperature | distinct-2 | Self-BLEU ↓ | Judge score |
|---:|---:|---:|---:|
| 0.2 | 0.214 | 0.71 | 8.4 |
| 0.7 | 0.398 | 0.52 | 8.1 |
| 1.0 | 0.521 | 0.39 | 7.6 |
| 1.3 | 0.603 | 0.31 | 6.2 |

The trade-off is clear: higher temperature buys diversity at the cost of judged quality. 표가 넓어지면 모바일에서 어떻게 보이는지도 확인해야 합니다.


## What to do about it

- Keep a fraction of **human-written data** in every generation of training.
- Filter for quality *per mode*, not globally, so rare but valid answers survive.
- Track a diversity metric alongside quality, and stop when it drops below a threshold.

| Strategy | Cost | Effect on diversity | Notes |
|---|---|---|---|
| Mix in real data | Low | Strong | Needs a held-out human corpus |
| Per-cluster filtering | Medium | Medium | Requires embeddings and clustering |
| Diversity-aware reward | High | Strong | Easy to game; needs careful design |
